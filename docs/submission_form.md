# 공모전 접수 양식 (11/15 마감)

> 공유 링크·첨부자료에 개인정보·계정정보·개발자 실명이 노출되지 않도록 확인할 것.
> 상세 기술요건은 공식 안내를 따르며, 필요 시 별지 추가 가능. 원천: [기획서 v3.0](./AI_Group_Driving_Specification_v3.md)

## 1. 앱 한 줄 소개
여러 대가 함께 달릴 때, 일행이 어디서 왜 멀어졌는지 차가 먼저 알려주고 말 한마디로 경유·통화까지 이어 주는 그룹 주행 앱 **오디(Odee)**.

## 2. 기획 배경
명절 귀성·캠핑·동호회 투어처럼 2~4대가 함께 이동할 때, 일행 차가 분기점을 놓치거나 충전소로 빠지면 운전자는 주행 중에 메신저를 확인하거나 전화를 겁니다. 전방 주시가 가장 필요한 고속 구간에서 폰을 집게 되는 순간입니다.
기존 위치 공유 앱은 점의 위치만 보여 줄 뿐 **왜 벗어났는지**(길을 잘못 든 것인지, 배터리가 부족해 충전하러 간 것인지)를 알려 주지 못해, 결국 확인 통화가 필요합니다. 그렇다고 그룹 통화를 계속 켜 두면 차 안 가족 대화가 노출되고 음악·내비 안내와 섞여 피로합니다. 일행 중 타사 차량이나 목적지에서 기다리는 가족은 같은 흐름에 들어오지도 못합니다.
이 문제는 차량 데이터(배터리·연료·기어·제동)와 순정 내비·음성 비서·차량 오디오를 함께 다룰 수 있는 **차량 앱**이어야 해결됩니다.

## 3. 앱 주요 기능 및 차량 특화 요소
| 기능 | 해결하는 문제 | 차량 특화 요소 |
| :--- | :--- | :--- |
| **이탈 맥락 판별** | 일행이 왜 벗어났는지 모름 | `Vehicle SDK` 배터리·연료 잔량·감속 + 주변 충전소로 "분기점 실수" vs "충전 목적" 구분 |
| **선제적 공동 경유** | 각자 충전하느라 흩어짐 | 일행 중 한 대의 주행가능거리가 남은 거리의 115% 미만이면 공통 충전 휴게소 제안 → `NaviHelper SDK`로 순정 내비에 경유지 자동 반영 |
| **적응형 안전 UX** | 주행 중 화면 조작 | 속도·`Gear`·`Brake`로 안전 등급 산출. 주행 중엔 지도를 가리지 않고 배너+음성만, 정차 시에만 전체 화면 |
| **음성 우선 결정** | 손을 써야 하는 확인·응답 | `TTS` 1문장 브리핑 + `STT` 응답, **Gleo**에 3개 기능 등록("오디 일행 어디쯤이야?", 알림 수락, "마이크 꺼줘·통화 끊어줘") |
| **필요할 때만 그룹 통화** | 상시 통화의 피로·프라이버시 | 이탈·추천 순간에만 연결, AAOS `AudioFocus`로 음악·안내음 30% 감쇄, 급제동 시 수신 음성 20%로 감쇄 |
| **앰비언트 라이트 알림** | 화면을 봐야 상황을 앎 | `Light SDK`로 이탈 Amber·추천 Cyan·통화 Green, 종료 시 원래 색 복원 |
| **무설치 합류** | 타사 차량·대기 가족 단절 | QR·링크로 웹 컴패니언 합류, 카카오내비·TMAP·네이버지도 딥링크, 대기자가 우회 경로 추천(3분 이상 단축일 때만 알림) |
| **흔적 없는 세션** | 위치 개인정보 | 위치·차량 상태는 메모리에서만 처리, 도착·종료 즉시 세션과 통화방 파기 |

## 4. 주요 사용 시나리오
**A-1. 분기점 실수 (2호차 운전자 실수)**
고속도로 90km/h 주행 중 2호차가 판교 IC를 놓침 → 1호차는 지도 화면 그대로, 배너와 음성 "2호차가 판교 분기점을 지나쳐 경로를 이탈했습니다. 5분 지연이 예상됩니다. 그룹 보이스를 연결할까요?" → 운전자 "연결해줘" → 음악이 작아지며 통화 연결, 조명 Green → "오디 통화 끊어줘"로 종료.

**A-2. 충전 목적 이탈 (가족 여행)**
2호차가 배터리 16%로 충전소에 진입 → 1호차에 "2호차(배터리 16%)가 판교 급속충전소에 진입했습니다. 함께 경유(+6분)할까요?" → 수락하면 순정 내비에 같은 충전소가 경유지로 들어감.

**B. 목적지 대기자의 길 안내 (마중 나온 가족)**
목적지에서 기다리는 가족이 받은 링크로 앱 설치 없이 합류 → 정체를 보고 우회 경로를 추천 → 서버가 8분 단축을 확인한 경우에만 운전자에게 Cyan 알림 → 수락 시 내비 경로 갱신과 동시에 가족과 통화 연결.

**C. 언제든 음성으로 확인**
운전 중 "오디 일행 어디쯤이야?" → 화면 전환 없이 "2호차 EV9 32km 앞, 14:45 도착." 목적지 도착 시 세션 기록 즉시 삭제.

## 5. 개발 계획 (Pleos Connect 구현 범위와 SDK/API 사용)
**구현 완료 (Pleos Connect v2.1.0 에뮬레이터 실측)**
- 차량 앱: AAOS Kotlin/Jetpack Compose. 관제 서버: Node.js(TypeScript, Fastify·WebSocket). 그룹 통화: 오픈소스 LiveKit(WebRTC). 웹 컴패니언: React PWA. 공통 프로토콜은 Zod 스키마로 차량·서버·웹이 공유
- `Vehicle SDK`: `EvBattery`·`Fuel`·`Gear`·`Brake` 리스너 → 텔레메트리, 안전 등급
- `Light`: `setAmbientLightBrightnessColor` 상황별 색상 및 복원
- `FusedLocation`: 위치·속도, 순항 5~10초 / 분기·이탈 구간 1초 가변 전송
- `NaviHelper`: 그룹 목적지·수락 경유지 `requestRoute`, 결정 후 `requestNavigationScreen`으로 순정 내비 복귀
- `TTS`/`STT`: 1문장 브리핑, 알림 중 음성 응답 (자격증명 시 HYBRID, 없으면 ON_DEVICE)
- `Gleo Interface`: `schema.json` 3개 기능(`SHOW_GROUP_LOCATION`, `ANSWER_GROUP_ALERT`, `CONTROL_VOICE_CALL`), 화면 전환 없는 서비스 응답, Gleo 전용 권한으로 수신기 보호
- AI 판단: 룰 기반 1차 판정(이탈 유형·에너지) + LLM 브리핑 문장(키 없으면 룰 기반 문장으로 폴백)

**본선(12월)까지**
- 실차·Gleo 실발화 검증, 통화 내용 기록·정차 중 요약(Pleos STT, 오프라인·룰 기반)
- 다음 안내 지점 이름(`NaviHelper` TBT)을 "어디쯤?" 응답에 반영(예: "구미IC 방면")

## 6. 기대효과 및 발전 가능성
**사용자 가치:** 그룹 주행 중 폰 조작 제거(이탈 알림 → 결정까지 음성 8초 이내 목표), 확인 통화·기다림 감소, 공동 충전 경유로 일정 단축, 타사 차량·가족까지 한 세션으로.

**타깃 고객:** ① 가족·지인 여행(명절 귀성, 캠핑) ② 차량 동호회·투어링 ③ 기업·기관 단체 이동 ④ 관광지 다중 렌터카·카셰어링. 반복 이동이 많은 ①②가 초기 핵심.

**예상 MAU·리텐션 (가정 기반 목표):** 그룹 주행은 매일이 아닌 명절·주말·여행에 몰리는 이벤트형 사용입니다. 출시 1년차 목표는 Pleos 커넥티드 활성 차량의 3%가 월 1회 이상 그룹 세션 참여, 컴패니언으로 합류하는 비(非)Pleos 일행·가족이 차량 1대당 평균 1.5명 추가되어 앱 사용자보다 넓은 노출을 만드는 구조입니다. 리텐션은 "월 2회 이상 사용 그룹 비율"로 측정하며 동호회·정기 여행 그룹 기준 3개월 리텐션 40%를 목표로 합니다. 수치는 파일럿 베타에서 실측해 보정합니다.

**확장 계획:**
1. 파일럿: 동호회·사내 행사 실차 베타로 응답 시간·오탐률 측정, 룰 보정
2. 정식 출시: Pleos App Market, 관제·통화 서버를 현대 자체 인프라로 이관(LiveKit 오픈소스라 설정만 변경), 커넥티드 서비스 구독 번들
3. 수익: 기본 무료(2~4대) + 대규모 그룹·장시간·고급 통화 프리미엄, 행사·렌터카·법인 대상 그룹 관제 대시보드 B2B, 충전소 제휴(추천 순위는 안전·효율 우선)
4. 서드파티 내비(TMAP·네이버·카카오) 실시간 경로 양방향 연동 ([로드맵](./future_roadmap_multimap.md))
